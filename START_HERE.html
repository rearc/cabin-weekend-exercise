The problem

Everything you need is in the chat. That's the problem.

The facts are scattered across four days of messages: who's in, which dates work, how much people can spend, who's bringing a dog, what people want to do. Some of it is in photo captions and edited messages. Some of it might be a joke, and nobody in the chat is going to tell you which.

Robert found eleven cabins and sent the search. There's a visitor guide for the area. And the group wants two things from you: a plan everyone can say yes to, and one thing you'll all do together.

Why a cabin weekend?

Because it has the same shape as real work: a long thread with the requirements buried in it, a pile of documents to compare, decisions only a person can make, and news that arrives after you've started. You don't need to know anything about cabins. You do need to notice what matters, write it down, and carry it forward without dragging the whole thread along.

How you'll work

Pack light: carry a file, not the conversation.

This is the technique from the slides. Break the job into phases, then for each phase:

  1. Iterate
    Work the phase

    One conversation with Claude. Ask, correct, decide.

  2. Compile
    Pack a file

    Save only what the next phase needs, and the decisions you made.

  3. Export
    Start fresh

    Type /clear, then mention your file with @ to begin the next phase.

↻ Repeat for each phase. Your files are the only thread between them.

Long threads rot.Screenshots, dead ends and corrections pile up, and the model weighs all of it.
Corrections don't stick.The model can't tell your fixed answer in turn five from the wrong one in turn three.
A file is a decision.A small file holds what you decided, and nothing you didn't.

Before you /clear, check your file

Step 1 · Before you open Claude

Plan your phases.

Look through your inputs first, so you know what you're working with. Then decide your phases. Each phase takes something in (screenshots, or a file you made earlier) and hands one small file on. The last phases hand on the messages.

A plan for a different job, so you can see the shape

Booking a team dinner for twelve from a long Slack thread and five restaurant menus.

  1. The thread: Slack screenshots in, people.md out.
  2. The menus: people.md and the menus in, shortlist.md out.
  3. The pick: both files in, plan.md out.
  4. The booking: plan.md in, the message out.

Step 2 · Open Claude Code

Four moves are all you need.

Open Claude Code in this folder. It will ask for your phases first: paste the plan you copied. From then on, start each message with the phase you're in, so Claude stays on it.

Give Claude a file
Type @ and part of its name, then pick it. Mention several at once.
Save a phase
Ask Claude to save it to a file. If it asks to create or edit the file, allow it. The file appears at the top of this folder.
Start fresh
Type /clear. Claude forgets the conversation; your files stay. In VS Code you can also start a new conversation.
Check your file
Open it in the editor and read it. It's yours to fix by hand too.

You'll learn these properly later in the workshop. For now, use them as given.

Step 3 · One phase at a time

Work through it.

Your phases will probably look something like the ones below. Open a hint when you're stuck in one: each has a nudge first and a bigger hint behind it. None of them gives you the answer.

Reading the chatGetting started
NudgeAsk Claude to transcribe the screenshots before you decide anything. Everything on the screen counts, not just the typed lines.
Bigger hint
Bigger hintPhotos, captions, reactions and edited messages are all part of the chat. Some messages could be serious or a joke: for each one that would change a number or a choice, you decide, and write the decision and your reason into your file.
Packing a phase fileEnd of every phase
NudgeBefore you save, tell Claude what the next phase will look up in the file, and ask it to check the draft against that.
Bigger hint
Bigger hintTest it: could a friend who never saw the chat start the next phase from this file alone? Anything that lives only in the conversation is gone after /clear.
Choosing a cabinThe search and listings
NudgeThe search page rules some cabins out on its own. Open only the listing pages you still need.
Bigger hint
Bigger hintListing pages have what the search page doesn't: fees, house rules and the calendar. Compare the total for your dates, not the nightly price.
When news arrivesAny time
NudgeGive Claude the message with @. Update your file first, then rerun the phase it affects from the file, in a fresh session.
Bigger hint
Bigger hintGo through your phases and ask what the news changes in each. Then ask who is allowed to know it, and write that rule into the file as well.
Picking the activityAfter the cabin
NudgeCheck each option against everyone who's coming, not just the person who suggested it.
Bigger hint
Bigger hintThe facts that rule an option in or out are inside each entry's text, not in its title. Read every entry against everyone in your file, and keep the activity near the cabin.
Writing the two messagesThe last phases
NudgeWrite each message in its own fresh session, from your plan alone. If something is missing, fix the plan, not the message.
Bigger hint
Bigger hintRead each draft as the person getting it. What could they work out from it?
